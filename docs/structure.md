# 구조

## 폴더

```
main.py                  실행 파일
cancel_catcher/
  macro.py               매크로 엔진: 구역 클릭, 빈자리 찾기, 20분마다 새로고침
  screen.py              화면 캡처, 색 찾기, 색 글자 해석
  hotkeys.py             전역 단축키
  ui/
    components.py        공통 UI 컴포넌트와 스타일
    window.py            메인 창: 컴포넌트 조립, 매크로 · 단축키 연결
    gallery.py           컴포넌트 미리보기 페이지
tests/
  test_macro.py          엔진 · 색 · 단축키 테스트 (Qt 없음)
docs/                    문서
```

`macro.py`, `screen.py`, `hotkeys.py`는 Qt를 모릅니다. Qt는 `ui/` 안에서만 씁니다.

## 스레드

- **GUI 스레드**: 창을 그립니다. Qt 위젯은 이 스레드에서만 건드립니다.
- **매크로 스레드**: 시작할 때 하나 만듭니다. 구역 클릭, 색 찾기, 새로고침을 모두 이 스레드에서 차례로 해서 마우스 조작이 엉키지 않습니다. 시작할 때마다 실행 번호(`run_id`)를 올려서, 정지 직후 다시 시작해도 이전 루프가 스스로 끝납니다. 루프 안에서 에러가 나면 멈추고 빨강 램프로 알립니다.
- **단축키 스레드**: pynput이 만듭니다. 콜백에서 예외가 밖으로 나가면 pynput이 감지를 꺼 버리므로, `Hotkeys.on_press`에서 모두 잡아 상태줄로 알립니다.

매크로 스레드나 단축키 스레드에서 화면을 바꿀 때는 `MainWindow.gui(fn)`으로 GUI 스레드에 넘깁니다 (Qt 시그널).

## 좌표

마우스, 화면 캡처, 찾을 영역 모두 모든 모니터를 합친 실제 픽셀 좌표를 씁니다. 프로그램은 Qt 기본값인 모니터별 DPI 모드로 돕니다.
드래그 화면(`RegionPicker`)은 Qt 좌표를 받으므로 모니터 배율을 곱해 실제 픽셀로 바꿉니다. 모니터의 왼쪽 위는 두 좌표가 같습니다.

## 공통 컴포넌트

`ui/components.py`의 컴포넌트는 모양을 직접 정하지 않고 상태를 속성으로만 바꿉니다. 모양은 전부 `stylesheet()`에 있습니다.
색은 세 가지만 씁니다: 초록(실행 중, 찾음, 저장됨, 시작), 빨강(오류, 정지), 노랑(대기, 저장 안 된 필수 칸).

미리보기는 모든 컴포넌트를 상태별로 실제 Qt로 그려 HTML 한 장으로 만들고 브라우저로 엽니다.

```powershell
uv run python -m cancel_catcher.ui.gallery
```

## 테스트

```powershell
uv run python -m tests.test_macro
```

실제 마우스와 키보드 대신 기록만 하는 가짜를 씁니다. 에러 경로를 확인하는 테스트는 일부러 낸 에러의 traceback을 출력합니다.

## 알려진 점

- 창 폭은 420px로 고정이고, 높이는 내용에 맞춰 바뀝니다. 줄바꿈되는 글이 있으면 Qt가 창 높이를 모자라게 잡아 버튼이 눌리므로 `MainWindow.fit_height()`에서 직접 맞춥니다.
- 새로고침 뒤 G, H를 누르기 전 대기 시간(0.2초)은 사이트 로딩 속도를 반영하지 않습니다.
